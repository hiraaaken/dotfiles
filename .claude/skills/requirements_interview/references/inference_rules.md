# 要件推測ルール

設計書またはソースコードから要件を推測する際のルールと質問生成パターン。

## CRUD機能要件の推測

APIエンドポイントのHTTPメソッドからCRUD操作を推測:

| 検出パターン | 推測 | 確認質問 |
|---|---|---|
| GET /resources | 一覧取得 | ページング・検索条件はあるか |
| GET /resources/{id} | 個別取得 | 閲覧権限の制限はあるか |
| POST /resources | 新規登録 | バリデーションルール、登録時の業務ルール |
| PUT/PATCH /resources/{id} | 更新 | 排他制御、更新可能フィールドの制限 |
| DELETE /resources/{id} | 削除 | 物理削除か論理削除か、削除条件 |

**リソースのグルーピング**: パスの最初の非パラメータセグメントでグルーピング。
例: `/api/v1/orders/user/{userId}` → `orders` リソースに帰属。

## ビジネスロジックの推測

Service層でCRUD以外のメソッドを検出した場合、個別に業務目的を質問。
CRUD判定に使う除外メソッド名:
`findAll, findById, save, delete, deleteById, create, update, getAll, getById`

## 依存ライブラリからの推測

| 依存キーワード | 推測カテゴリ | 質問すべき内容 |
|---|---|---|
| spring-security | セキュリティ | 認証方式、ロール、外部IdP |
| flyway, liquibase | 運用 | マイグレーション手順、ロールバック |
| kafka, amqp, rabbitmq | 外部連携 | メッセージ種類、配信保証、連携先 |
| spring-batch | 機能 | ジョブ一覧、スケジュール、リカバリ |
| cache, redis | 性能 | キャッシュ対象、TTL、無効化 |
| spring-mail | 外部連携 | 送信タイミング、テンプレート、送信先 |
| validation | 非機能 | 業務固有ルール、多言語対応 |
| spring-cloud | アーキテクチャ | マイクロサービス構成、サービス間通信 |
| thymeleaf, freemarker | 機能 | SSR画面の存在、SPA併用 |

## エンティティからの推測

- テーブル名・フィールド名から業務ドメインの意味を質問
- リレーションからカスケード動作を質問
- OneToMany/ManyToMany で件数上限を質問

## コードから推測不可 → 常に質問する項目

1. **ビジネス背景**: 利用者、業務課題、前身システム
2. **性能要件/SLA**: レスポンスタイム目標、同時接続数、可用性
3. **ログ・監視**: 出力先、保持期間、監視ツール、アラート条件

## confidence レベルの基準

| レベル | 基準 | 例 |
|---|---|---|
| high | コードに直接的な証拠がある | `@RestController`のエンドポイント |
| medium | 間接的な証拠から推測 | 依存ライブラリからの機能推測 |
| low | コードからは推測不可 | 性能要件、ビジネス背景 |
