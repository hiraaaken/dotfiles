## 21:59 - IdeaVimのsplit移動競合を修正

### Technical Findings
- JetBrains の `SplitVertically` / `SplitHorizontally` で作られる editor split は、Vim の window とは別レイヤーなので、`<C-w>h/j/k/l` をそのまま使うと移動対象が噛み合わないことがある。
- IdeaVim の `sethandler <C-H/J/K/L> n:vim` を入れると、normal モードでは `Ctrl-h/j/k/l` の入力優先権を IDE ではなく IdeaVim 側に寄せられる。
- `GotoSplitterLeft` / `Right` / `Up` / `Down` に直接つなぐと、Android Studio の split 間移動を Vim ライクなキーに素直に対応づけられる。

### Design Decisions
- **既存の操作意味は維持**: `Shift-h/l` のバッファ移動と `Ctrl-h/j/k/l` の split 移動は変えたくない前提だったため、キー自体は変えずに実装先だけ JetBrains Action に寄せた。
- **`<C-w>h/j/k/l` も同じ Action に統一**: `Ctrl-h` と Vim 本来の window コマンドが別挙動になるのを避けるため、どちらも同じ splitter action にそろえた。

### Learning Keywords
- `IdeaVim sethandler` - IDE と Vim のキー入力優先権の切り替え
- `GotoSplitterLeft` - JetBrains の分割ウィンドウ移動 Action 名
- `Android Studio keymap conflicts` - Ctrl 系ショートカット衝突の確認用
